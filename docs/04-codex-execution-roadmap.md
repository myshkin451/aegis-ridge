# 04. Codex 分阶段开发路线图（M1–M6）

> **核心策略**：**切忌在一个窗口里发一句话让 Agent 一口气写完整个项目。**
> 推荐严格按照下面 **6 个垂直里程碑（M1 → M6）** 推进：每个阶段开一个**全新的 Codex Session** → 完成后先跑构建与测试 → 你亲自在浏览器里肉眼看视觉并微调 1–3 轮 → 满意后 `git commit` 存档 → 开新 Session 进入下一阶段。

---

## 为什么 M1 的肉眼验收最重要？

3D 项目的灵魂是**第一眼的建筑比例、山体形态、光影高级感与镜头手感**。
M1 代码量最小、调整成本最低——如果 M1 出来的山体丑、灯光发灰、比例不对，**务必在 M1 当场调到你看着心里发爽为止**，再进入 M2。不要带着别扭的视觉底子往后堆功能。

### 阶段 M1：工程初始化、半山腰地形与建筑骨架定调

> **前置**：新建 Codex Session。

```text
请先完整阅读仓库根目录的 AGENTS.md、docs/PROGRESS.md，以及 docs/01-shelter-engineering-spec.md、docs/02-visual-and-ux-spec.md、docs/03-technical-architecture.md。

本轮任务仅完成里程碑 M1（工程脚手架 + 验证 Harness + 3D 山体沙盘 + 建筑骨架与楼层剥离）：
1. 初始化 Vite + React + TypeScript(strict) + Tailwind CSS + Three.js (@react-three/fiber, @react-three/drei) + Zustand + lucide-react + Vitest 项目配置，并在 package.json 中配置 typecheck / test / build / verify（串联前三项）脚本；编写首批 Vitest 几何自检测试（校验 B1–B4 所有房间网格无重叠、不侵占固定竖井与主走廊）。
2. 建立 src/types/shelter.ts、src/data/floors.ts、src/data/defaultBlueprint.ts（先完整写入 L2/L1/B1-B4 所有房间的精确网格坐标与基础元数据）和 src/scene/utils/coords.ts（唯一坐标换算源）。
3. 实现高质量的 3D 沙盘骨架：
   - 半山腰等高线阶梯地形（支持 exterior 全山外观 / cutaway 地质半剖面 / xray 整山透视 三种模式平滑切换）；
   - 地表科研观测站（L1 隐蔽车库与门厅 + L2 观测厅与玻璃温室 + 屋顶气象雷达罩与光伏翼）的精致建筑体块；
   - 6m 花岗岩防护岩层缓冲带，以及地下 B1–B4 四层（每层显式包含楼板、3.0m 净高隔墙、0.9m 顶部机电夹层空腔、主干走廊、5 个对齐的垂直核心竖井与西侧平硐入口）；
   - 按 docs/02 的配色与布光标准，做出高级建筑微缩模型质感（柔和阴影、层次光感、禁止塑料感）。
4. 实现基础 HUD：顶部视图模式切换（全山/半剖/X光）与相机视角预设（全景/地表/地下剖面）、左侧楼层剥离条（ALL/L2/L1/B1/B2/B3/B4 + 夹层显隐开关）。

完成前请严格按 AGENTS.md 执行 npm run verify、更新 docs/PROGRESS.md、自动 git commit 并尝试 git push origin main，然后告诉我启动预览后最值得重点检查的画面细节。
```

**M1 你的验收清单**：
- 打开 `localhost` 旋转缩放，第一眼是否像精致的建筑微缩沙盘而不是粗糙方块？
- 切到“地质半剖面”和“X 光”时，地表建筑、6m 岩层、地下 4 层和竖井是否严丝合缝对齐？
- 点左侧 `B1`~`B4` 切层是否干脆利落？确认满意后 `git commit -m "feat(m1): init project, terrain, shelter shell and floor slicing"`。

## 给开发者的实用微调技巧（在 Codex 中）

- **单步反馈要具体**：如果觉得某个画面不好看，不要只说“不够好看”，可以结合截图直接说：“山体阴影太硬、饱和度偏高，把岩层调成更偏冷灰哑光；B3 水培架的紫白灯再柔和一点并加一点微弱发光”。
- **一次只修一类问题**：验收微调时，把同一轮想改的 3–5 个视觉或交互小问题打包成一条消息发给当前 Session，修完再统一检查。
- **善用 Git 回滚**：如果某个新 Session 改乱了架构，直接 `git checkout .` 或回退到上一个里程碑 commit，比在坏代码上反复修补快得多。
